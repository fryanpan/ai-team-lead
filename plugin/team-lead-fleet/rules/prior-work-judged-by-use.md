# Prior work: say what each tool does, what it misses, and who uses it

**Bryan, 2026-11-26, on a prior-work note that listed 14 crash analysis methods to adopt:** "please for each tool be clear in the research doc about what it does well and what it does not and is the tool actually in use broadly (research that leads nowhere is useless). We don't need more complex models that lead nowhere. We need clarity that prioritizes limited resources."

So for each tool, method or study that a prior-work note lists, write three lines:

1. **Does well.** The one thing it does that we should copy.
2. **Doesn't do.** What it leaves out, or where it misleads. One example: it leads only to hotspot fixes. Another: it buries the reader in a sparse matrix where a few cells matter.
3. **In use.** Who actually uses it to decide spending, with evidence. Name the agency or city, and the decision it feeds. If you find no evidence of use, say so. A tool nobody uses goes in a "dropped" list with that reason. It does not go under "adopt".

Judge each item by whether it helps someone decide where limited money goes. A more complex model is not a reason to adopt it. If it adds inputs and changes no ranking, leave it out.

Why: the note listed 14 sources as "what to adopt" in one line each. It never said which ones drive decisions anywhere. Bryan had to ask twice before each source was opened and judged.
