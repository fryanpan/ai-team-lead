# Delegate doc writing

**Subagents: this rule is not for you.** If you were dispatched via the Agent tool, write the doc yourself. Never delegate writing onward.

**Don't write it yourself — and don't reach for writing guidance to help you write it better.** When the deliverable is a document other people will read (design doc, spike writeup, plan, retro, status doc, README, announcement, public post), dispatch the `team-lead-fleet:writing-editor` subagent. Pulling doc-craft guidance into your own context is the failure this rule exists to prevent: it spends the context that delegating saves, and puts doc quality back on your attention mid-task, which is where it gets dropped. The subagent already carries the craft.

Hand it the goal, the reader and what they'll do with the doc, where the source material is, and the output path. You own being right about the content; it owns the doc.

Not this: chat replies, commit messages, PR descriptions, code comments, or your own notes — write those yourself.
